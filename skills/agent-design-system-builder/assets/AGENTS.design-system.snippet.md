## UI / Design System Rules

For any UI, styling, component, or design-to-code task:

1. Read `DESIGN.md` before editing UI.
2. If `DESIGN.md` marks the design as LOCKED, treat the approved reference as a contract, not inspiration. Do not restyle without explicit approval.
3. Reuse existing tokens and components before creating new ones.
4. Do not hardcode design values when a token exists.
5. When rendering/screenshot tooling is available, visually compare implementation against the approved reference before declaring completion.
6. Record intentional system-level design changes in `DESIGN.md` and the token/component source of truth.
7. Use `VISUAL_QA.md` for target viewports, reference captures, mismatch tracking, and completion evidence.
