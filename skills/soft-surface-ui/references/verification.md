# 验收：检查可观察结果

## 静态比较

在相同视口、相同缩放下比较参考和实现。先看整体：画布颜色、列数、列宽、行距、卡片高度；再看字体换行、内边距、圆角、阴影；最后看图标与图片取景。记录差异，不凭印象写“100% 一致”。

建议至少检查桌面、窄屏两个实际目标尺寸，例如 1440 × 1000 与 390 × 844；这些是测试样例，不是固定产品断点。原参考是裁切录屏，不能拿整张 2048px 截图直接和 1440px 页面比绝对位置。

## 动效行为

- 从短便签到长收件箱，再切到深色 Focus：外壳应连续变化，内容不能硬切或被持续缩放。
- 连续快速点左右箭头：最后的目标正确，不闪回、不累积旧内容、不遗留不可点的透明层。
- 改成 0.5×：退出延迟和进入时间应一起放慢；网格不能比卡片更快或更慢。
- 如果显示高度读数，确认它与容器当前尺寸一致；固定圆角就显示固定值。
- 图片加载完、字体变化、文本换行后仍能正确测量，不截断重要信息。
- 离开页面、关闭研究态后自动轮播和过时的计时器按预期停止。

## 交互与无障碍

- 仅使用键盘打开、切换、关闭；Escape 关闭后焦点回到合理位置。
- 退出中的内容不可被 Tab 进入；dialog 中的控制条仍能点击。
- 输入有标签，图表选择有语义，图标按钮有可理解的名称。
- 开启减少动态效果后再操作：仍可切换内容，持续媒体模拟应停止或降级。
- 搜索无结果、便签长文本、图片返回、窄屏和 200% 缩放不破坏主要交互。
- 数值、活动和媒体行为如为演示数据，不能在交付中声称真实联网。

## 本包的验证范围

仓库校验验证 Skill 元数据、目录、索引及必需文件；`node --check` 验证示例 JavaScript 语法。它们不证明渲染、动态流畅度、屏幕阅读器或浏览器兼容性已经通过。

本次原始网页交付完成过语法与本地素材引用检查，未完成浏览器逐帧验收。之后的维护者实际运行这些检查后，应记录视口、浏览器、操作和结果，避免沿用未获得的通过结论。
