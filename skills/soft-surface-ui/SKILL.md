# Soft Surface UI

把“轻盈、安静、连续”的卡片界面落实为可复用的视觉约束与交互。它是一套风格与动效配方，不是必须照搬的七卡片产品模板。

## 先确定使用方式

- **复刻参考**：已有截图、视频或确认过的 Figma 时，优先保持其布局、内容和比例。不要再生成一套新概念图来替换参考。
- **迁移风格**：只想采用这种审美时，保留目标产品的信息架构与功能，仅迁移视觉语言和适合的动效。
- **研究示例**：直接运行 `assets/example/index.html`。画廊展示本次七个组件，Morph 模式额外包含视频中的 Focus 状态。

若项目有 `agent-design-system-builder` 或现成的设计治理，沿用其 Design Contract、token 和组件规范；该 Skill 只提供本风格的具体取值与实现方法。没有这些工具时，本 Skill 可独立使用。用户的新要求优先于示例值。

## 实施路径

1. **提取证据。** 区分截图可见事实、视频可见行为和实现推断。视频无法读取时，明确动效只是推演；不要声称逐帧匹配。几何数值按截图的内容区域测量，排除录屏黑边和浏览器缩放。
2. **锁定风格。** 读 [visual-system.md](references/visual-system.md)，记录白底、文字层级、列宽、间距、圆角、边框、阴影、强调色、素材取景。把实际选定值写入项目的 `DESIGN.md` 和已有 token 系统。`assets/primitives/tokens.css` 是可复制的起点。
3. **实现静态形态。** 先使卡片静止时的比例与参考一致。功能文字、控件和图表用原生 UI 实现；照片使用用户素材或有合适许可的素材。不要把整个截图作为页面。
4. **实现连续变化。** 读 [motion-system.md](references/motion-system.md)。将外壳尺寸/底色与内容出现/消失分开驱动，保持文字字号稳定。选择成熟的现有动效库或示例中的原生 Web Animations API，避免为此替换整个技术栈。
5. **适配产品。** 读 [integration.md](references/integration.md)，处理现有组件复用、Figma 可用性、响应式、真实交互和素材来源。演示控制条、网格和玻璃光标仅在需要动效研究时启用。
6. **验收。** 使用 [verification.md](references/verification.md) 的高价值检查。能渲染时比较截图并实际操作；不能渲染时，说明只完成了哪些代码检查，不声称视觉或流畅度已经通过。

## 保持这些特征

- 纯白画布和白色表面，使用边框与微弱阴影建立层级。
- 大留白、紧凑的信息层级；布局服从产品内容，不强迫所有页面成为卡片网格。
- 系统无衬线 UI 字体；衬线字体只用于引用、便签等确有语义差异的内容。
- 约 24px 的柔和卡片圆角，内层图片约 7–8px；统一间距和图标笔画。
- 蓝色等强调色只用于状态、选择与数据重点；图片承担主要色彩。
- 过渡呈现“同一个容器正在改变”，而不是两张完整卡片互相缩放替换。
